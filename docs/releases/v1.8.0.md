# dev-api-proxy v1.8.0

This release adds OmniAi support, provider-labelled desktop model selection, optional Xingchi session filtering, and updated documentation.

## Providers and model selection

- OmniAi has isolated `/omniai/v1` and `/omniai/v1beta` routes and its own API-key fallback.
- OmniAi Chat remains native; Xingchi and FreeGG Chat use the existing Responses conversion policy.
- Picker IDs such as `omniai/gpt-6.1-sol` route to the selected upstream and remove the prefix before forwarding.
- Cross-provider choices never reuse the original connection's provider key.
- Generated catalogs retain original IDs as hidden compatibility entries and separate compaction fingerprints by provider.
- Responses input-token counts are routed only where the selected provider's allowlist supports them.

## Session filtering and reliability

- Xingchi filtering is opt-in: mode `0` disabled, mode `1` metadata filtering, and mode `2` session-header rotation at `88` requests.
- Native relays have bounded recovery for eligible rate-limit, transport, and server failures.
- Primary recovery recognizes maintenance-related failures before response commitment.
- Existing no-replay, disconnect cleanup, local authentication, and upload/SSE limits remain in effect.
- Retries can repeat accepted work and cause additional charges; they do not provide exactly-once execution.

## Startup, versioning, and docs

- Both apps now report the shared release version `1.8.0`.
- Startup displays all providers, credential sources, session-filter mode, and active limits in one summary.
- Normal system-Python use and missing fallback keys no longer produce misleading warnings.
- The updater compiles the complete runtime-module set before signalling a restart.
- The README and reliability guide are rewritten, with focused setup/reference guides and credential-free examples.

## Upgrade

Wait for active requests to finish, update the checkout, and restart the proxy.
Keep the existing `.env`; do not replace private keys with the example file.
The built-in upload-limit fallback is 20 MiB. `.env.example` configures 1 GiB.

For the ChatGPT main picker, generate a full Codex catalog and follow `docs/clients.md`.
Restart ChatGPT desktop after changing its provider or catalog configuration.
OpenCode provider-config changes are watched; a config edit alone does not require a service restart.

Keys, private desktop configs, and user-specific model metadata are not included in this release.
Automated validation uses simulated upstreams and loopback fault servers, not paid model generation.
